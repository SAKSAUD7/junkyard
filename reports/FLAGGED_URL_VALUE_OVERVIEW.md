# Flagged legacy URLs — value ranking and what to do about them

Generated by `scripts/rank_flagged_urls_by_equity.py`
Input: `reports/legacy_redirects_flagged.csv` (10,363 rows)
Output: `reports/flagged_urls_by_value.csv` (10,363 ranked rows, 22 columns)
All numbers below are printed by that script, not estimated. Re-running it under
two different `PYTHONHASHSEED` values produced byte-identical CSVs.

## 1. Read this before quoting any number to the client

**There is no per-URL inbound link data in this repository.** The only file with a
Target URL column, `junkyardsnearme_backlinks.csv`, contains 52 rows and *every one
of them points at the site root*. The 35,768-row audit
(`JYNM_Final_35768_Backlinks_Audit.csv`) is outbound — JYNM pages linking to
qualityautoparts.com, all with the identical sitewide footer anchor "Quality Auto
Parts". Neither file can tell us how much PageRank a specific legacy URL received.

So `value_score` is an explicitly defined **proxy**, not measured equity:

```
score = 100 * (0.40*evidence + 0.25*recoverability + 0.20*shape + 0.15*link_mass)

evidence        1.00  the path appears in a real Semrush crawl
                0.35  the path only appears via "Internal Node Expansion"
                      (the audit extrapolated it from a URL pattern)
link_mass       min(outbound footer rows for that path, 6) / 6
recoverability  word overlap (Jaccard) between the legacy yard slug and the
                closest live vendor name in backend/vendors_recovered.json;
                x0.4 when several live yards share that name,
                x0.5 when the state in the slug contradicts the candidate
shape           junkyard_named 1.00 | vendor_named 0.90 | numeric_id 0.85
                | parts_facet 0.45 | other 0.30
```

Higher score = "worth spending human time on first". It is an *ordering*, not a
guarantee that the URL carries traffic.

## 3. The finding that changes the workload

The flagged list is not 10,363 decisions. It is **2,789 yard profiles**, each of
which was crawled as four URLs:

| Legacy URL family | Rows |
|---|---|
| `<yard>/inventory` | 2,481 |
| `<yard>/photos` | 2,481 |
| `<yard>/reviews` | 2,481 |
| `<yard>` itself (and other shapes) | 2,920 |

Resolving one yard resolves up to four URLs. Of the 2,789 yards, **2,025 already
have a ready-to-map target**, so the real manual backlog is roughly **764 yards**,
not 8,335 URLs.

Shape distribution of the flagged URLs: `vendor_named` 7,457 · `junkyard_named`
2,768 · `parts_facet` 111 · `other` 27.

## 4. Recommended order of work

1. **Apply the 1,852 "ready + target already live" rows.** Their destinations are
   the same `/junkyards/<state>/<pk>-<slug>` pages the shipped 45,886-rule nginx map
   already 301s to a 200, so no new destination is being invented.
2. **Verify the 314 "ready but new destination" rows with curl** before adding them
   (same check that validated the 46-rule sample in `GSC_MIGRATION_CHECKLIST.md`).
3. **Decide the 65 state-conflict rows individually.** Example:
   `/junkyards/north-carolina/10002079-wagners-auto-salvage-durham-nc` only matches
   `NC Auto Salvage (Hendersonville)` in the live data — same state, different
   business. Mapping it would send a caller to the wrong yard.
4. **Ask the client about the 7,443 yards that are simply gone** from the recovered
   vendor data. They need a business answer (did the yard close?), not a technical
   one. A 410 Gone or a 301 to `/junkyards-by-location` are both defensible; leaving
   them as soft-404s is not.
5. **Batch the 111 `/parts/<part>/<region>` facet pages** into one rule to
   `/auto-parts`; they are thin, duplicated listing pages and carry the least value.

Filter on `needs_client_decision = no` for the automatable subset; everything with
`needs_client_decision = yes` is a decision that must not be resolved by a script.

## 6. What this document deliberately does not claim

- It does not claim any of these URLs is indexed by Google, or that any backlink
  still exists.
- It does not claim `value_score` correlates with traffic; no traffic data was
  available for this analysis.
- It does not authorize adding redirects. `proposed_target_if_unique` is a
  suggestion derived from a name comparison; only rows also marked
  `target_already_live = yes` point at a page already proven to serve HTTP 200.
- Original CSVs under `reports/` and the Semrush exports were read, never modified.
